🐘 Перенос PostgreSQL

Пошаговая инструкция: дамп  →  перенос  →  восстановление
Шаг 1 Создаём дамп на старом сервере
Зайдите на старый сервер по SSH и выполните pg_dump в каталог /tmp.
sudo -u postgres pg_dump -F c -b -v -f /tmp/proton.dump proton
-F c custom (сжатый бинарный) -b включить BLOB‑объекты -v подробный вывод /tmp/proton.dump путь к дампу proton имя базы
ls -lh /tmp/proton.dump
✅
Убедитесь, что файл создан и имеет ненулевой размер.
Шаг 2 Перенос дампа на новый сервер
С того же терминала (на старом сервере) скопируйте файл на новый сервер через scp.
scp /tmp/proton.dump user@new-server-ip:/tmp/
user — пользователь на новом сервере new-server-ip — IP нового сервера
📁
Если /tmp недоступен для записи, укажите другую папку (например, домашнюю).
Шаг 3 Подготовка нового сервера
Зайдите на новый сервер, проверьте PostgreSQL и создайте пустую базу proton.
ssh user@new-server-ip sudo systemctl status postgresql sudo systemctl start postgresql # если не запущена sudo -u postgres createdb proton
⚠️ Если база уже существует и вы хотите перезаписать:
sudo -u postgres dropdb proton   затем снова createdb proton
Шаг 4 Восстанавливаем дамп
Используйте pg_restore для восстановления из custom‑дампа.
sudo -u postgres pg_restore -d proton -v /tmp/proton.dump
-d proton база для восстановления
⚙️
Альтернатива: если хотите, чтобы pg_restore сам создал базу из дампа:
sudo -u postgres pg_restore -C -d postgres -v /tmp/proton.dump
Шаг 5 Проверка восстановления
sudo -u postgres psql -d proton -c "\dt"
список таблиц
sudo -u postgres psql -d proton -c "SELECT count(*) FROM имя_таблицы;"
замените имя_таблицы
🔍
Убедитесь, что данные присутствуют и структура корректна.
Шаг 6 Очистка временных файлов
После успешного восстановления удалите дамп на обоих серверах.
sudo rm /tmp/proton.dump
старый сервер новый сервер

📌 Важные нюансы

🧩 Версии PostgreSQL
Желательно, чтобы версии на старом и новом серверах совпадали (или на новом была новее). Иначе возможны проблемы совместимости.
👥 Пользователи и роли
pg_dump одной базы не сохраняет пользователей и роли кластера. Создайте их вручную на новом сервере и выдайте привилегии.
🔐 Права доступа
У пользователя, под которым выполняется scp, должны быть права на запись в целевую папку (обычно /tmp доступен).
📦 Размер дампа
Для больших файлов используйте rsync --partial — он умеет докачивать при обрыве связи.
💡 совет Если на старом сервере есть дополнительные пользователи/роли — уточните версию psql --version и pg_dump --version, чтобы перенести их корректно.
