Запуск и управление службой
Основные команды для управления PostgreSQL на сервере.
Управление службой (Linux)
sudo systemctl start postgresql
sudo systemctl stop postgresql
sudo systemctl restart postgresql
sudo systemctl status postgresql
sudo systemctl enable postgresql   # автозапуск
Управление службой (Windows)

Через PowerShell (от администратора):

Start-Service postgresql-x64-16
Stop-Service  postgresql-x64-16
Restart-Service postgresql-x64-16
Get-Service   postgresql-x64-16

Или через services.msc — найдите службу postgresql-x64-16.

Подключение к PostgreSQL
Как войти в psql и основные команды внутри.
Linux — локально

PostgreSQL создаёт системного пользователя postgres. Войдите от его имени:

sudo -u postgres psql
sudo -u postgres psql -d mydb     # сразу к нужной БД
TCP — логин + пароль
psql -h localhost -p 5432 -U myuser -d mydb
psql -h 192.168.1.10 -p 5432 -U myuser -d mydb   # удалённо
Команды внутри psql
\l           список баз данных
\c mydb      переключиться на БД
\dt          таблицы текущей БД
\du          список пользователей
\conninfo    текущее подключение
\q           выйти
\?           справка
Работа с базами данных
Создание, просмотр, удаление и резервное копирование.
Создание
-- войдите: sudo -u postgres psql
CREATE DATABASE mydb;

-- с кодировкой и владельцем:
CREATE DATABASE mydb
  OWNER myuser
  ENCODING 'UTF8'
  LC_COLLATE 'ru_RU.UTF-8'
  LC_CTYPE  'ru_RU.UTF-8'
  TEMPLATE template0;
Просмотр
\l
SELECT current_database();
SELECT datname FROM pg_database;
Удаление
Нельзя удалить БД, к которой вы подключены. Сначала: \c postgres
DROP DATABASE mydb;
DROP DATABASE IF EXISTS mydb;
Бэкап и восстановление
# бэкап:
pg_dump -U postgres mydb > mydb.sql

# восстановление:
psql -U postgres mydb < mydb.sql

# бинарный формат (быстрее):
pg_dump -Fc -U postgres mydb > mydb.dump
pg_restore -U postgres -d mydb mydb.dump
Пользователи и права
Создание ролей, назначение привилегий, смена паролей.
Создание
CREATE USER myuser WITH PASSWORD 'secret123';

-- с правом создавать БД:
CREATE USER myuser WITH PASSWORD 'secret123' CREATEDB;

-- суперпользователь (осторожно):
CREATE USER myuser WITH PASSWORD 'secret123' SUPERUSER;
Назначение прав
GRANT ALL PRIVILEGES ON DATABASE mydb TO myuser;

-- права на таблицы (после \c mydb):
GRANT ALL ON ALL TABLES    IN SCHEMA public TO myuser;
GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO myuser;
Управление
ALTER USER myuser WITH PASSWORD 'newpassword';
ALTER USER myuser CREATEDB;           -- добавить право
ALTER USER myuser NOCREATEDB;         -- убрать право

\du                                    -- список ролей
DROP USER myuser;
Удалённый доступ — Linux-сервер
Четыре шага чтобы принимать подключения с любого IP.
1
postgresql.conf — разрешить слушать все адреса
sudo nano /etc/postgresql/16/main/postgresql.conf

Найдите и измените:

#listen_addresses = 'localhost'
listen_addresses = '*'           # принимать со всех адресов
2
pg_hba.conf — разрешить подключения
sudo nano /etc/postgresql/16/main/pg_hba.conf

Добавьте в конец файла:

# конкретный пользователь и БД:
host  mydb  myuser  0.0.0.0/0  scram-sha-256

# все пользователи, все БД:
host  all   all     0.0.0.0/0  scram-sha-256
Используйте scram-sha-256 — современный безопасный метод. Старый md5 не рекомендуется.
3
Перезапустить PostgreSQL
sudo systemctl restart postgresql
4
Открыть порт 5432 в firewall
# UFW:
sudo ufw allow 5432/tcp
sudo ufw status

# iptables:
sudo iptables -A INPUT -p tcp --dport 5432 -j ACCEPT
Проверка подключения
# с другой машины:
nc -zv YOUR_SERVER_IP 5432
psql -h YOUR_SERVER_IP -p 5432 -U myuser -d mydb
Удалённый доступ — Windows-сервер
Те же принципы, что на Linux — два конфига + брандмауэр.
1
Найдите файлы конфигурации

По умолчанию PostgreSQL устанавливается сюда:

postgresql.conf
C:\Program Files\PostgreSQL\16\data\postgresql.conf
pg_hba.conf
C:\Program Files\PostgreSQL\16\data\pg_hba.conf
Редактировать нужно от имени администратора. Откройте Notepad через «Запуск от имени администратора» и откройте файл через него.
2
postgresql.conf — разрешить все адреса

Откройте файл и найдите строку listen_addresses. Она может быть закомментирована:

#listen_addresses = 'localhost'

Замените на (или добавьте новую строку):

listen_addresses = '*'

Также убедитесь что порт не изменён:

port = 5432
3
pg_hba.conf — добавить разрешение

В конец файла добавьте строку. Формат: тип, база, пользователь, адрес, метод:

# конкретный пользователь и БД:
host  mydb  myuser  0.0.0.0/0  scram-sha-256

# все — для тестовой среды:
host  all   all     0.0.0.0/0  scram-sha-256
IPv6 — если нужно разрешить и для IPv6-адресов, добавьте вторую строку:
host all all ::/0 scram-sha-256
4
Перезапустить службу PostgreSQL

PowerShell (от администратора):

Restart-Service postgresql-x64-16

Или через services.msc: найдите службу → правая кнопка → «Перезапустить».

5
Брандмауэр Windows — открыть порт 5432

PowerShell (от администратора):

New-NetFirewallRule `
  -DisplayName "PostgreSQL 5432" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 5432 `
  -Action Allow

Или вручную: Брандмауэр Windows → Входящие правила → Создать правило → Порт → TCP → 5432

Если сервер находится за роутером — также пробросьте порт 5432 в настройках роутера (NAT/Port Forwarding).
6
Проверка

С Windows (PowerShell):

Test-NetConnection -ComputerName YOUR_SERVER_IP -Port 5432

С Linux:

nc -zv YOUR_SERVER_IP 5432
psql -h YOUR_SERVER_IP -p 5432 -U myuser -d mydb
Если TcpTestSucceeded: True — порт доступен и PostgreSQL слушает.
Клиенты для подключения к PostgreSQL
pgAdmin 4
Официальный GUI. Servers → Register → Server → вкладка Connection: хост, порт, БД, пользователь, пароль.
бесплатноWindows / Linux
DBeaver
New Connection → PostgreSQL → заполнить Host, Port, Database, User, Password → Test Connection.
бесплатноWindows / Linux / Mac
TablePlus
Удобный нативный клиент. Create new connection → PostgreSQL → ввести данные.
платный / trial
psql (CLI)
Стандартная утилита командной строки. Входит в установку PostgreSQL на любой ОС.
встроенWindows / Linux
